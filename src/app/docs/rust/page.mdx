# Rust crate and CLI

<StatusBadge status="implemented" label="Available in v0.8.0 (crates.io)" />

[![crates.io](https://img.shields.io/crates/v/evalsuite.svg)](https://crates.io/crates/evalsuite) [![docs.rs](https://img.shields.io/docsrs/evalsuite)](https://docs.rs/evalsuite) [![CLI](https://img.shields.io/crates/v/evalsuite-cli.svg?label=evalsuite-cli)](https://crates.io/crates/evalsuite-cli)

The metric engine behind the Python package is a standalone Rust library. It gives the same numbers as `evalsuite-python`: every function is checked against fixtures generated by the Python implementation (more than 36,000 cases, relative tolerance 1e-12 or tighter), so a value computed in Rust, Python, the browser, R or Julia is the same value. API documentation: [docs.rs/evalsuite](https://docs.rs/evalsuite).

## Install

<CodeBlock lang="bash" status="implemented" statusLabel="v0.8.0" code={`
cargo add evalsuite            # the library
cargo install evalsuite-cli    # the \`evalsuite\` command
`} />

## Use

<CodeBlock lang="rust" status="implemented" statusLabel="v0.8.0" code={`
use evalsuite::classification::{self as cls, Average, Opts};
use evalsuite::{generation as gen, regression, stats};

let y_true = [0, 1, 1, 0, 1];
let y_pred = [0, 1, 0, 0, 1];
let f1 = cls::f1(&y_true, &y_pred, &Opts { average: Average::Binary, ..Opts::default() })?;
let rmse = regression::rmse(&[3.0, 2.5, 4.0], &[2.8, 2.7, 3.6], None)?;
let bleu = gen::bleu(&[vec!["the cat sat on the mat"]], &["the cat sat on a mat"], &gen::BleuOpts::default())?;
`} />

Modules cover classification, regression, calibration, clinical (diagnostic accuracy, decision curves), statistics (bootstrap BCa, DeLong, McNemar, permutation and rank tests), segmentation (Dice, IoU, HD95, surface distances), detection (COCO mAP), text generation (BLEU, chrF, TER, ROUGE, METEOR, CodeBLEU), retrieval (NDCG, MRR, MAP), QA, RAG, safety, agents, long-context, uncertainty and monitoring (sliding-window metrics, PSI, Kolmogorov–Smirnov drift, alerts).

## Command-line tool

<CodeBlock lang="bash" status="implemented" statusLabel="v0.8.5" code={`
evalsuite metrics
evalsuite evaluate predictions.csv --y-true label --y-pred pred --y-prob prob -f markdown
evalsuite evaluate predictions.csv --y-true y --y-pred yhat --metrics mae,rmse,r2
evalsuite diagnostic predictions.csv --y-true disease --y-pred test_positive
evalsuite calibration predictions.csv --y-true label --y-prob prob
evalsuite text outputs.csv --prediction output --reference reference -o scores.json
`} />

The Rust CLI reads CSV, TSV and JSON and writes text, JSON, CSV or Markdown (chosen by `-f` or by the output file's extension). The Python package installs its own `evalsuite` command with the full report, plotting and comparison workflow; see the [CLI reference](/docs/cli).

## Speed

Fastest of repeated runs, single process, on a 2-core Linux machine; "Python" is the `evalsuite-python` reference implementation (NumPy / SciPy / sacreBLEU kernels). Text rows are EvalSuite 1.0; the others 0.8.5.

| Workload | Rust | Python | Speed-up |
| --- | ---: | ---: | ---: |
| Accuracy, 1,000,000 labels | 0.73 ms | 7.9 ms | 10.8× |
| ROC AUC, 100,000 | 6.9 ms | 9.4 ms | 1.4× |
| Median absolute error, 1,000,000 | 8.5 ms | 17.5 ms | 2.1× |
| BCa bootstrap of MAE, 10,000 × 2,000 resamples | 100 ms | 362 ms | 3.6× |
| Welch t-test, 10,000 | 0.064 ms | 0.105 ms | 1.6× |
| NDCG@10, 10,000 queries | 4.7 ms | 71 ms | 15.3× |
| MRR, 10,000 queries | 4.1 ms | 42 ms | 10.4× |
| Dice, 512 × 512 | 2.2 ms | 4.5 ms | 2.0× |
| chrF, 1,000 sentences | 9.4 ms | 11.4 ms | 1.2× |
| TER, 1,000 sentences | 95 ms | 128 ms | 1.3× |
| BLEU, 1,000 sentences | 9.9 ms | 7.7 ms | 0.8× |

Where Python is still level or ahead, it already runs compiled kernels (NumPy's SIMD loops or sacreBLEU's C extension paths); the Rust numbers there buy portability (WebAssembly, C, R, Julia) rather than speed.
